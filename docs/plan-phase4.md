# Phase 4 — Eyedropper + จานสีจากรูป marker

## Context

Phase 3 ทำให้คนซ่อนวาง ล็อค ระบายสี และบันทึกลง DB ได้ครบวง แต่จานสียังเป็น
**สีตายตัว 10 สีโทนดิน** (`hideApp.js:13 PALETTE`) ซึ่งเป็นตัวยืนยันว่ากลไก brush ทำงาน
ไม่ใช่ตัวที่ทำให้พรางได้จริง

Phase 4 เปลี่ยนจานสีให้มาจาก **รูป marker เอง** สองทาง:
1. **Eyedropper** — แตะที่รูป marker เพื่อดูดสีจริงตรงจุดนั้น
2. **Swatch ที่ extract อัตโนมัติ** — สีเด่นทั้งรูป + สีเฉลี่ยราย cell 4×4

ผล Spike B บอกว่า camouflage อ่านออกจริง และผล Phase 0 บอกว่าตัวช่วยที่ได้ผลที่สุดคือ
**คนซ่อนเห็นผลผ่านกล้องจริงระหว่างระบาย** (ปุ่ม peek ที่มีแล้วใน Phase 3)
Phase 4 คือการเอาสีที่ "ถูกต้องตามไฟล์ต้นฉบับ" มาใส่มือคนซ่อน ให้เขาไม่ต้องเดาสี

> **ข้อควรรู้ล่วงหน้า (จาก review Phase 0):** eyedropper อย่างเดียว **ไม่ทำให้พรางเนียน**
> เพราะสีที่กล้องเห็น ≠ สีในไฟล์ (auto-exposure / auto-WB / tone curve ต่างกัน 10–30%)
> Phase 4 ลดงานเดาสีลงมาก แต่ตัวปิด loop จริงคือสายตาคนผ่านปุ่ม peek
> การชดเชยด้วย per-channel gain เป็นงาน **Phase 8** ไม่ใช่ตอนนี้

## Steps

### 4.1 `markerSampler.js`

```js
export async function loadMarkerSampler(url, maxDim = 1024)
// → { W, H, aspect, sample(u, v, radius = 4) }
```

กฎที่ต้องทำตาม (ทั้งหมดมีเหตุผลจากที่พิสูจน์มาแล้ว):

- **`img.crossOrigin = 'anonymous'`** — ไม่มีอันนี้ canvas จะ tainted อ่านพิกเซลไม่ได้
  (same-origin อยู่แล้ว แต่ใส่ไว้กัน CDN ในอนาคต)
- **`getImageData` ครั้งเดียวตอนโหลด** เก็บ `Uint8ClampedArray` ไว้ — ห้ามเรียกต่อการแตะ
  เพราะ readback จาก GPU-backed canvas ทำให้สะดุดตรงจังหวะที่ผู้ใช้รอผลทันที
- **เฉลี่ยเป็นวงกลม r≈4px ไม่ใช่พิกเซลเดียว** — JPEG ringing และเม็ดสกรีนงานพิมพ์
  ทำให้พิกเซลเดียวแกว่งมาก บนพื้นผิวมีลายซึ่งคือสิ่งที่เกมนี้ต้องการพอดี
- **ปล่อย canvas หลัง decode** (`canvas.width = canvas.height = 0`) — เก็บแค่ typed array
  (เหตุผลเดียวกับ S8 ที่แก้ใน mask.js: iOS canvas memory)
- ย่อลง `maxDim` 1024 ถ้ารูปใหญ่กว่า

**ตรวจ:** โหลด marker จริง แล้ว `sample(0.5, 0.5)` ต้องได้สีที่ตรงกับกลางรูปเมื่อเทียบด้วยตา

### 4.2 `palette.js` — extract สีตอนไหน?

**ตัดสินใจ: extract บน client ตอนเปิดหน้า hide ไม่ใช่ตอน upload**

เหตุผล: schema มี `palette_json`/`grid_json` รออยู่แล้วและแผนเดิมบอกให้ทำตอน upload
แต่ **`upload.html` ยังไม่มีของจริง** (ตอนนี้ redirect ไป spike) ถ้าผูก Phase 4 กับ upload
จะบล็อกกันเอง — และ `markerSampler` ก็ถอด pixel มาแล้วอยู่ดี การ extract เพิ่มคือ ~40 ms

→ Phase 4 ทำบน client · **Phase 6 ย้ายไปทำตอน upload แล้วเก็บลง DB** (คอลัมน์รออยู่แล้ว)
API ไม่ต้องแก้ตอนนี้

```js
export function extractPalette(data, W, H, n = 8)   // bucket 4³ = 64 ถัง + เฉลี่ยในถัง
export function gridPalette(data, W, H, G = 4)      // สีเฉลี่ยราย cell
```

- bucket-แล้ว-เฉลี่ย ดีกว่าใช้จุดกลางถัง (ซึ่งเห็น quantise ชัด) และคุ้มกว่า k-means
- ตัดสีที่ซ้ำกันเกินไปออก (ระยะกำลังสองใน sRGB < ~800)
- stride ต้องเป็นจำนวนเท่าของ 4 · sample ~40k จุดพอ

**แสดง 2 แถวใน HUD:**
- **"สีเด่น"** — สีเด่นทั้งรูป
- **"ตามโซน"** — สีเฉลี่ยราย cell 4×4 ← **แถวนี้คือแถวที่ช่วยพรางจริง**
  เพราะการพรางเป็นเรื่อง *เฉพาะที่* ไม่ใช่ค่าเฉลี่ยทั้งรูป

### 4.3 โหมด eyedropper ใน `hideApp.js`

เพิ่ม sub-mode ของ PAINT (ไม่ใช่ mode ใหม่ใน state machine หลัก):

```
PAINT + tool=BRUSH      → ลากเพื่อระบายสี   (พฤติกรรมเดิม)
PAINT + tool=EYEDROPPER → แตะที่รูปเพื่อดูดสี แล้วสลับกลับเป็น BRUSH อัตโนมัติ
```

- ปุ่มสลับ tool อยู่ในแถบ `.paint-only`
- ตอน tool=EYEDROPPER: ใช้ `pickAnchorPlane` → `localToMarkerUV(p, marker.aspect)`
  → `sampler.sample(u, v)` → `brush.setColor(...)` → เพิ่มสีลงแถว "สีที่ดูดมา" (เก็บ 6 สีล่าสุด)
- **ดูดสีจาก "ทุกที่บนระนาบ marker" ได้ รวมทั้งใต้ตัวโมเดลเอง** — นั่นคือจุดที่คนซ่อนต้องการที่สุด
  (`localToMarkerUV` ไม่สนใจว่าตัวโมเดลทับอยู่ไหม จึงได้ฟรี)
- ต้อง clamp/ปฏิเสธถ้า uv หลุด [0,1] (แตะนอกขอบรูป) → ไม่เปลี่ยนสี พร้อมข้อความสั้นๆ
- **กลับเป็น BRUSH อัตโนมัติหลังดูด 1 ครั้ง** — คนซ่อนอยากดูดแล้วระบายต่อทันที
  ไม่ใช่มานั่งสลับ tool

**ต้องใช้ tap ไม่ใช่ drag:** `bindPointer` มี `{ tap }` ใน `end()` อยู่แล้วจาก Phase 3
(`distance < 12 && < 600ms`) → eyedropper ทำงานที่ `end()` เมื่อ `tap === true`
ไม่ใช่ที่ `start()` ไม่งั้นการขยับกล้องเล็กน้อยจะดูดสีมั่ว

**ทุก handler ยัง `return` เมื่อ `!session.visible`** — กฎเดิมจาก Phase 3

### 4.4 HUD

- 3 แถว swatch: **สีเด่น** · **ตามโซน** · **ที่ดูดมา** (แถวหลังว่างตอนเริ่ม)
- swatch ที่เลือกอยู่ต้องเห็นชัด (`aria-pressed` + outline — pattern เดิมจาก Phase 3 ใช้ได้เลย)
- แสดงสีปัจจุบันเป็นวงกลมตัวอย่างข้างปุ่ม brush
- `PALETTE` แบบ hardcode ใน `hideApp.js:13` **ลบออก**

### 4.5 ทางถอย

ถ้า `marker.imageUrl` เป็น null หรือโหลด/decode ไม่ได้ (เช่น marker เก่าที่ไม่มีรูป):
→ **ถอยไปใช้จานสีตายตัวชุดเดิม** + ซ่อนปุ่ม eyedropper + แจ้งเหตุผลสั้นๆ
โหมดคนซ่อนต้องยังใช้งานได้ ห้ามพังทั้งหน้าเพราะรูปหาย
(F4 ทำให้ marker ที่ `ready` ต้องมีรูปแล้ว แต่ข้อมูลเก่ายังอยู่)

## Verification

**ระดับหน่วย (node + import โมดูลจริง — pattern เดียวกับที่ใช้ตรวจ Phase 3):**
```
extractPalette / gridPalette กับ buffer ที่รู้คำตอบล่วงหน้า:
  - รูปครึ่งซ้ายแดงล้วน ครึ่งขวาน้ำเงินล้วน → extractPalette ต้องคืนแดงกับน้ำเงิน ไม่ใช่ม่วง
  - gridPalette(G=4) กับรูปเดียวกัน → cell คอลัมน์ซ้ายต้องแดง คอลัมน์ขวาต้องน้ำเงิน
  - รูปสีเดียวล้วน → ต้องไม่คืนสีซ้ำ 8 ตัว (ตัวกันซ้ำต้องทำงาน)
sampler.sample() กับรูปสังเคราะห์ที่รู้ค่าพิกเซล → ต้องตรงภายใน ±2
```
การทดสอบด้วยรูปที่รู้คำตอบสำคัญกว่าดูด้วยตา เพราะ bug ของ palette
มักออกมาหน้าตา "สีเทาๆ ดูพอใช้ได้" ซึ่งกลืนไปกับผลที่ถูกต้อง

**ระดับเครื่องจริง (มือถือ + marker พิมพ์กระดาษด้าน + ngrok):**
1. เปิด `/hide.html?marker=<id>` → แถว "สีเด่น" และ "ตามโซน" ต้องขึ้นสีที่ **เห็นได้ว่ามาจากรูปนั้น**
   (ถ้าออกมาเทาหมด แปลว่าเฉลี่ยรวมกันเกินไป — bug)
2. ล็อคตำแหน่ง → เลือก eyedropper → แตะบนรูปตรงจุดที่มีสีเด่นชัด
   → swatch "ที่ดูดมา" ต้องได้สีนั้น และ tool ต้องกลับเป็น brush เอง
3. ระบายทับตัวโมเดล → กด peek สลับ → **นี่คือการทดสอบจริงว่า Phase 4 มีประโยชน์:**
   ใช้เวลาน้อยกว่าเดิมมากไหมในการทำให้กลืน เทียบกับจานสีตายตัวของ Phase 3
4. แตะ **นอก** ขอบรูป marker → ต้องไม่เปลี่ยนสี ไม่ crash
5. ดูดสีตรงจุดที่ตัวโมเดลทับอยู่ → ต้องได้สีของ **รูป** ไม่ใช่สีที่ระบายไว้
6. บันทึก → `GET /api/hides/<id>` → ตรวจว่า texture ที่เก็บมีสีที่ดูดมาจริง

**การทดสอบที่ชี้ขาดว่า F4 แก้ถูก:** ใช้ marker ที่ **ไม่ใช่จตุรัส** (เช่น card 372×674, aspect 1.81)
แตะที่ **มุมบนซ้าย** ของรูป — สีที่ได้ต้องเป็นสีของมุมบนซ้ายจริง
ถ้า `aspect` ผิด จุดที่ดูดจะเลื่อนไปตามแกน y แบบเป็นสัดส่วน ซึ่งจะเห็นชัดที่สุดที่ขอบ
